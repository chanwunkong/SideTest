# 自動觸發範圍稽核（2026-11-23）

單位：格 = 64 單位（`ax64 >> 6`），不是 32，也沒有為等角投影加倍；範圍欄位（seek 等）一律是「格」，要換像素才乘 64（`near_begin(x, y, seek * 64)`）。

## 結論
- 原版規則面（命令 0xf／0x10／0x11／0x12／0x13、觸發區、怪物視野、小動物）沒有發現放大：單位都是格（64），沒有 2 倍、沒有格／像素混用。
- 真正放大的是**觸控適配層**：攻擊鍵的備用挑目標（門 5 格、道具 3 格、NPC 3 格）加上「打完怪按著不放就接著開門／說話」。已全部縮小並加上「打過敵人就不再接著動」。這些仍標「觸控適配」，只用來**選目標**；實際到位條件仍是上表原版值。
- 沒做／沒驗證：
  - 沒有在瀏覽器實際點過；`make web` 只確認編得過。
  - 1a／2a／4a／4b 這輪是沿用舊反編譯記載，沒有重讀 0x489730。
  - 4c 地上道具點擊命中框（±24×±20）原版數字沒查。
  - 怪物 seek 的實際資料值（RoleMdl 欄 24）沒逐隻檢視。若使用者仍覺得某隻怪太敏感，需要指名那隻，核對它的 seek。
