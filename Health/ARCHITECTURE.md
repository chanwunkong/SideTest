# 健康管理專案架構

最後更新：2026-10-30。這份文件記錄已確認的產品方向、架構和開發順序。

## 1. 產品原則

- 幫使用者管理目標，不替使用者設定目標。目標和達成條件都由使用者決定。
- 打開就能用，不做第一次使用流程，也不在使用前詢問問題。
- 把健康徹底數值化，同時盡量減少操作步驟。
- 首頁只放重點，不放分析。提醒用顏色和圖示，不用文字待辦。
- 不替使用者假設習慣。例如喝水份量每次都能不同。
- 一開始提供粗略的大項，想看更細的使用者可以自行增加。
- 不做動畫。
- 功能可以拆成不同網頁，資料庫共用。
- 全部功能支援繁體中文和英文。

## 2. 整體架構

```text
只要計時器的人        想管理全部的人
      │                    │
  訓練計時網頁          健康管理網頁      未來其他工具
      └────────────┬───────┘────────────┘
                   ▼
        共用核心：登入、資料、語言、風格
                   ▼
           同一個 Firebase 資料庫
```

- 網頁可以獨立使用。只用計時器的人不必看到健康管理，也可以不登入，資料先存在裝置上。
- 同一帳號登入後，計時器完成的訓練會自動出現在健康管理。
- 資料只存一份，各網頁用同一套格式讀寫，不互相複製。
- 網頁優先放在 `chanwunkong.github.io` 底下，登入狀態才能共用。未來改用其他網域時，資料庫仍共用，但要各登入一次。

### 目標資料夾

```text
core/      共用核心：healthStore、資料類型清單、語言檔、共用樣式
Health/    健康管理
Timer/     訓練計時
```

共用核心和 `Timer/` 已建立。兩個網頁讀寫同一份資料。

## 3. 名稱

| 舊名稱 | 新名稱 | 說明 |
|---|---|---|
| Hangboard／指力計時器 | 訓練計時 | 懸吊、有氧間歇、重訓都能用 |
| Routine／課表 | 訓練 | 一次要做的內容 |
| Block | 步驟 | 計時、次數、循環 |
| Goal／週期 | 排程 | 哪幾天做哪個訓練 |
| 無 | 計畫 | 一段時間的安排，例如「瘦身三十天」 |

```text
步驟 → 訓練 → 排程 → 計畫
```

計畫包含運動安排和每日飲食攝取。

## 4. 首頁：生理功能總覽

版面由上而下：

1. 日期與「週｜月」切換。
2. 週或月表格：每張卡片一列，每天一欄。
3. 生理功能總覽標題、編輯、設定。
4. 兩欄、同尺寸的卡片。

表格狀態只有三種：

| 狀態 | 顯示 | 意思 |
|---|---|---|
| 做到 | 卡片的顏色 | 當天符合條件 |
| 沒做到 | 空框 | 當天該做但沒有做到 |
| 不需要 | 小點 | 不需要做、還沒到，或開始記錄前 |

卡片規則：

- 預設四張：身體組成、飲食、睡眠、活動。
- 數量不限，可新增、移除、排序。
- 卡片形式有單一數字和多項數字，多項最多 3 項。未來可增加其他形式。
- 預設有紀錄就算做到。使用者可以自行設定條件和需要做的日子。
- 資料分兩種：每日累計隔天重新計算；體重、體脂這類最新數值會保留，並標示幾天前。
- 更新頻率由使用者設定：不固定、每天、每週幾次、每月幾次、指定星期。身體組成和活動預設不固定。
- 每週或每月幾次只在今天提示，過去的日子不算沒做到。
- 同一張卡片任一項有新數值就算做到。想分開追蹤時，拆成不同卡片。
- 今天做到時圖示變彩色，沒做到時為灰色。
- 點表格上的日期或格子，下方卡片切換成那一天的紀錄，也能從那天補記。
- 點卡片看該項目的月曆和快速記錄。
- 卡片的選擇和順序跟著帳號保存。
- 運動使用紅色。步數等 Apple 健康接好後再顯示。

## 5. 資料設計

```text
users/{uid}/
├─ profile/main          基本資料、語言、首頁卡片
├─ events/{id}           所有原始紀錄
├─ goals/{id}            目標，含生效日期
└─ attachments/{id}      照片、心率序列等大型資料
```

未來新增的訓練、排程、計畫沿用同一個使用者路徑，集合名稱在對應階段定案。

每筆事件使用同一個外殼：

```js
{
  id, type, schemaVersion,
  occurredAt, tzOffset, date,
  source, externalId,
  data, raw, attachmentIds,
  createdAt, updatedAt, deletedAt
}
```

固定規則：

- 只存原始資料，彙總和趨勢都即時計算。
- 新增資料類型時，在類型清單加一項，不改資料庫結構。
- 欄位只增不改義。結構變更時版本加 1，並寫升級規則。
- 程式遇到不認識的類型要略過，但必須原樣保留。
- 單位統一存 kg、ml、mg、秒，顯示時再換算。
- 每筆紀錄保存發生時的時區。
- 使用者改目標時，只影響生效日之後的日子。
- 只有 `healthStore` 能讀寫資料庫。
- 使用者可以匯出全部資料。

舊版 `ClimbingToolbox` 的紀錄不搬移。舊資料留在原處，新版不讀取。

## 6. 中英雙語

- 介面文字全部放在語言檔，程式裡不直接寫顯示文字。
- 資料只存代碼和標準單位，顯示時再翻譯。
- 使用者自己寫的內容依原文保存。
- 分享的計畫由作者提供語言內容；缺少某語言時顯示原文。
- 預設跟隨裝置語言，也可以手動切換，設定跟著帳號保存。
- 新寫的頁面從一開始就使用語言檔。現有頁面之後再替換。

## 7. 飲食流程

App 不直接呼叫 AI，也不需要 API 金鑰。

1. 頁面提供 Gemini 提示詞。
2. 使用者在手機版 Gemini 傳照片。
3. Gemini 回覆規定格式的 JSON。
4. 使用者貼回 App，確認後存檔。

格式名稱是 `health-meal-v1`。解析失敗時顯示錯誤，不存入錯誤資料。

第一版分析：

- 今天的攝取項目。
- 最近 7 天的平均。
- 使用者自己設定的目標，以及目前和目標的差距。
- 目標用下限和上限設定：只填下限是至少，只填上限是至多，兩格都填是範圍。
- 飲食卡預設有紀錄就亮。使用者可以選擇全部目標達成才亮。

第一版不提供自動建議。

## 8. 運動紀錄

運動紀錄和訓練計時分開。沒有計時器也能建立訓練、排程和每日紀錄。

```text
動作 → 訓練 → 排程 → 紀錄
```

範例：

- 訓練：Cindy，一套是引體向上 5 次、伏地挺身 10 次、深蹲 15 次。
- 排程：每天做 Cindy，持續指定天數，目標套數可有可無。
- 紀錄：10 月 30 日做了 6 套。

### 動作庫

- 動作保存在 `exercises`，內容由使用者填寫，不預先放入範例。
- 動作可以有上層，例如深蹲 → 槓鈴深蹲 → 全蹲。累計次數可以合計到上層。
- 訓練的動作引用固定編號，並保留名稱。輸入新名稱時會自動加入動作庫。
- 動作可以填英文名稱。刪除動作時，下層會移到上一層，舊紀錄不變。

### 訓練模式

模式用清單管理，每個訓練只保存 `mode` 和該模式需要的設定。新增模式不影響舊訓練。

| 模式 | 階段 | 記錄內容 |
|---|---|---|
| 有做就好 | 第一版 | 是否完成 |
| 累積套數 | 第一版 | 當天幾套 |
| 限時最多 | 未來 | 規定時間內完成多少 |
| 指定完成 | 未來 | 多久完成指定內容 |
| 逐步增加 | 未來 | 依規則增加次數或套數 |

### 動作指標

指標全部選填，用同一份清單管理。每個動作可以選擇需要的指標。

```js
{ exercise: 'hang', metrics: { holdSec: 10, weightKg: 5, gripType: 'half', edgeMm: 20 } }
```

預留指標包含次數、維持秒數、重量、距離、握法和岩點寬度。未來可讓使用者建立自己的動作和指標。

### 紀錄詳細程度

同一筆紀錄支援不同詳細程度，由使用者決定：

1. 有做。
2. 當天套數。
3. 每套實際內容，可以記未完成的一套。
4. 休息時間。

- 休息時間是選填欄位，每個訓練可決定是否顯示。
- 預設畫面只顯示使用者需要的欄位。
- 紀錄要保存當天的動作內容。之後修改訓練，舊紀錄不變。
- 排程可以支援階段設定和單日例外，第一版先預留。

### 提醒

第一版用首頁表格的空框提醒，不做主動推播。之後如果需要，再評估 iPhone 主畫面推播、捷徑或提醒事項。

## 9. 訓練計時

訓練計時是記錄訓練的另一種方式，資料寫進運動紀錄的同一套結構。

課表可以只記錄，也可以加入計時內容。步驟有計時、次數、循環三種，循環可以放循環。訓練完成或中途保存時，會寫成一般運動紀錄。

- 編輯畫面一次顯示整份課表，循環用粗括號線連到裡面的步驟，底部只有一個新增。選中循環時，新增放進循環；其他情況放在最後。
- 點一行編輯。拖曳沿用舊版的 SortableJS，可以調整順序、拖進或拖出循環。刪除和複製放在編輯畫面裡。
- 重寫舊工具時保留已成熟的功能和函式庫，只重做版面與視覺。
- 訓練畫面背景是目前步驟的顏色，下一步也用自己的顏色顯示，並有時間軸、進度條和提示音。運動時不用看字也知道階段。
- 步驟結束時可以記錄數值和力竭，並帶入上次的值。中斷後可以續跑。
- 名稱使用課表、計時、次數、循環、組數，不使用自創名詞。

舊工具是巢狀訓練流程工具，功能包含計時、次數、循環、語音控制、螢幕常亮、中斷續跑、訓練紀錄和藍牙裝置。

做法：

- 做成獨立網頁，健康管理的運動頁放入口。
- 用新風格重做，舊邏輯先評估，能重用才保留。
- 新版實際用過後，再封存舊工具。
- HoldFocus 不屬於這個專案，維持獨立。

第一批範例：懸吊、有氧間歇、全身肌力，以及一份「瘦身三十天」計畫。

## 10. 計畫與線上分享

計畫格式一開始就設計成可分享的形式，內容包含每週運動安排和每日飲食攝取。

線上分享需要作者身分、公開權限、檢舉和內容審核。飲食內容涉及健康風險，範例要讓使用者自行決定是否採用。

## 12. 未來規劃

以下項目現在不做，資料結構要保留空間：

- 依運動和身體狀況，自動推薦飲食或訓練目標。
- 自動調整休息日和運動日的飲食標準。
- 個人化版面：比 Apple 健身的固定模板更自由。使用者可以選擇卡片大小和排列方式，並使用圓環、長條圖、趨勢圖等顯示形式，也可以保存自己的版面。
- 卡片內容自訂：使用者可以選擇每張卡片要顯示哪些數值或圖表。例如同一張活動卡顯示步數、距離和每小時長條圖。
- 休息與恢復分析。
- 運動分析：依身體部位追蹤負荷，例如今天大腿用量很高。
- 肌肉與關節分類由使用者決定：可以粗分大腿，也可以細分到單一肌肉；關節柔軟度和活動度也能作為追蹤項目。
- 動作對應部位：每個動作可以設定用到哪些肌肉或關節，再由紀錄自動累計和分析。這需要動作有固定編號，不能只靠動作名稱。
- 速度與爆發力分析：追蹤器或影片的原始資料存成序列資料，紀錄只存每組的平均速度、峰值速度和速度下降。訓練目的、訓練容量與肌肉恢復由這些資料計算。
- 分析模型要分版本，並標示為估計值。快肌與慢肌的參與程度無法只靠深蹲速度直接量測，只能作為推論。模型更新後可以用原始資料重算。
- 恢復時間先由使用者設定，之後再依紀錄和身體狀況提供估計。
- 動作庫：內容由使用者填寫，每個人保存自己的一份。動作可以有上下層，例如深蹲之下有槓鈴深蹲，再分全蹲和半蹲；分析時可以看細項，也可以合計到上層。
- 動作庫範本：使用者可以從網路下載別人的動作庫，匯入後複製到自己的動作庫並保留來源。之後對方修改或刪除，不影響已匯入的內容和舊紀錄。
- 攀岩動作分析。
- 趨勢線、熱量收支和恢復分數。
